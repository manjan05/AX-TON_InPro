## 1. 한 줄 소개

**InPro는 발명 접수부터 변리사 전달까지, 특허 담당자의 반복 업무를 AI로 잇는 서비스입니다.**

- 이름: **In**tellectual **Pro**perty(지식재산) + **In Pro**gress(진행 중). 발명이 출원까지 멈추지 않고 진행되게 한다는 뜻
- 발표용 한 줄: "Intellectual Property, 그리고 In Progress. 발명이 출원까지 멈추지 않고 진행되게 만드는 서비스입니다."
- 대상: 특허 전담 인력이 없거나 1~2명뿐인 연구개발 스타트업·중소기업 (대표·CTO·연구소장이 특허 업무를 겸임하는 회사)

## 2. 스토리: 왜 이 서비스가 되었나 (발표의 뼈대)

이 흐름 자체가 심사 점수(문제 정의)의 핵심입니다. 멘토님도 "가설이 깨지고 인터뷰로 진짜 페인포인트를 찾은 과정을 무조건 넣어라"고 했습니다.

1. **출발: 1차 발표 "대덕 NEXUS" (우수팀 선정)**
   - 문제 인식: "기술이 부족한 게 아니라 연결이 부족하다"
   - 공공연구기관 특허 중 58.7%가 미활용 (1차 발표 자료). 쓰이지 않는 출연연 특허를 조합해 기업 문제에 맞춰 제안하는 서비스였음
   - 하지만 근거가 공급 쪽 통계뿐이었고, 기업이 정말 특허를 살지는 확인하지 않았음
2. **현장으로: 멘토 "아이디어는 좋지만 근거가 필요하다" → 현직자 4명 인터뷰**
3. **무너진 가설: 기업은 특허를 사지 않는다. 피해 간다 (회피설계)**
4. **새로 찾은 니즈: 특허를 찾고, 읽고, 보완하고, 주고받는 반복 업무**
5. **서비스 전환: InPro (AI 특허 업무 자동화)**
6. **분야 집중 (2차 멘토링): "자신 있는 분야 하나로 좁혀 완성형으로 검증하라" → 가정용 공기청정기 필터의 형상**

## 3. 인터뷰 근거 (발표에 인용할 말)

| # | 누구 | 핵심 |
|---|---|---|
| #1 | 가전 제조사 연구 팀장급 (특허 조사·출원·침해 대응 경험) | "키워드로 찾으면 300건이 뜨는데 실제로 관련 있는 건 50건 정도." "한 건에 40페이지." 기업은 경쟁사 특허를 사기보다 회피 설계로 피한다 |
| #2 | 대학 반도체 연구원·스타트업 재직자 | "혼자의 기술로는 완제품을 만들기 어렵다." 특허를 찾아도 상용화 가능성은 문서만으로 모른다 |
| #3 | 대기업 통신 연구직 경험자 | 기술 추천은 구매로 이어지기 어렵다. 연구팀이 있으면 기존 특허를 피해 자체 특허를 낸다 |
| #4 | 기업 IP팀장 (서면 인터뷰) | 아래 |

**#4 IP팀장 핵심 인용** (발표 신뢰도의 핵심)
- "좋은 IP팀은 '안 된다'고 말하는 조직이 아니라, 위험을 설명하고 '어떻게 하면 할 수 있는지' 대안을 제시하는 조직입니다."
- "핵심은 '무엇을 출원할 것인가'보다 '경쟁사가 우회하기 어려운 어떤 권리를 만들 것인가'입니다."
- "가장 현실적인 방식은 AI가 수많은 문헌에서 후보를 압축하고, 사람이 중요한 문헌을 원문 기준으로 최종 검토하는 Human-in-the-loop 방식입니다."
- "기업이 비용을 지불할 가능성이 높은 가치는 '특허 10개 추천'이 아니라 '어떤 특허를 왜, 어떤 조건으로 도입해야 하는지 설명하는 것'에 가깝습니다."
- 실제 검토 순서: 발명 접수 → 기술 이해·발명자 인터뷰 → 선행기술 조사 → 특허성·사업성 검토 → 권리범위 설계 → 출원 여부·국가 결정 → (명세서·출원은 변리사) → 심사 대응
- 재작업이 생기는 때: 발명 초기 설명과 실제 설계가 다를 때, 사업 범위가 바뀔 때, 선행기술을 추가로 발견했을 때
- 스타트업에 강조: "외부 공개·전시·논문 발표 전에 출원 필요성을 확인하라"
- 실무에서는 조사를 한 번으로 끝내지 않고 개발 단계(기획→상세설계→설계변경→출시 전→출시 후)마다 반복한다

**InPro의 6단계는 #4가 말한 실제 검토 순서를 그대로 따릅니다.** 이게 "현업을 이해하고 만든 서비스"라는 근거입니다.

## 4. InPro 6단계 (앱 화면 기준)

앱 주소: 첫 화면 `/` (소개 페이지), 작업 화면 `/workspace`

| 단계 | 사용자가 하는 일 | InPro가 하는 일 | 화면에서 보여줄 포인트 |
|---|---|---|---|
| 1. 발명 접수 | 발명신고서 형식으로 입력 (명칭, 적용 제품, 문제, 기존 방식, 발명의 구성, 효과, 공개 예정일) | 기술 구성 초안(C1·C2·C3)과 빠진 항목을 뽑음, 접수번호 발번 | 오른쪽 "작성 완성도" 체크, 공개 D-day 경고 |
| 2. 기술 이해·보완 | 연구원에게 질문을 보내고 답을 받음 | 빠진 항목을 연구원이 바로 답할 수 있는 질문으로 바꿈 | "연구원에게 보내기" (메일·메시지 복사), 답변 진행 막대 |
| 3. 선행기술 조사 | 검색어 확정, 비교할 문헌 선택, 줄마다 확인 | 범위를 좁혀 검색하고, 왜 뽑혔는지 설명하고, 구성 × 문헌 매트릭스로 비교 | **검색 경로, "왜 선정?", 아깝게 탈락, 매트릭스(신규성·진보성 판정)** |
| 4. 특허성·사업성 | 검토서 초안 확인 | 다른 점 후보, 사업 중요도, 경쟁사 모방 가능성, 출원 방식 추천 | 지표 카드 3개, 문서형 검토서, AI 추천 카드 |
| 5. 권리범위 설계 | 구성별 구분(핵심·대체 가능·부가) 조정 | 구성마다 경쟁사가 대신 쓸 수단과 우회 난이도 | "핵심인데 우회가 쉬움" 경고 |
| 6. 출원 결정·전달 | 국내·해외 출원·영업비밀·보류 결정, 승인 | 승인된 버전만 묶어 변리사 전달자료 생성 | 승인 전 확인 패널, 공문서 형식 전달자료, 인쇄·PDF |

단계 밖에서 계속 도는 기능 2개
- **공개 전 출원 알림:** 논문·전시·제안 날짜를 넣으면 D-day와 경고 (#4 조언)
- **개발 단계별 재조사:** 설계가 바뀌면 다시 조사하고, 판단이 바뀐 구성만 재승인 (#4 조언, 이름의 "In Progress")

## 5. InPro가 똑똑하고 믿을 수 있는 이유 (차별점 설명용)

1. **원문 근거를 서버가 다시 확인한다.** AI가 "같은 구성이 있다"고 해도, 그 인용 문장이 원문(요약·청구항)에 글자 그대로 없으면 판단을 버리고 "근거 부족 / 확인 필요"로 낮춘다. AI가 지어낸 근거가 변리사에게 넘어가지 않는다.
2. **검색 결과를 설명한다.** 몇 건에서 몇 건으로 왜 줄었는지(검색 경로), 문헌마다 어떤 검색어가 제목·요약·청구항 어디에 걸렸는지, 상위 밖으로 탈락한 이유, 담당자가 뺀 이유까지 기록한다. 실무에서 조사 보고서에 남기는 "검색식과 제외 내역"과 같다.
3. **구성 × 문헌 매트릭스로 심사관처럼 본다.**
   - 신규성: 문헌 하나에 우리 구성이 전부 있는가
   - 진보성: 여러 문헌을 합치면 전부 나오는가 ("문헌 A + 문헌 B를 합치면…")
   - 어느 문헌에도 없는 구성 = 핵심 차별 구성 → 5단계 권리범위 설계로 이어짐
   - 판정은 AI가 아니라 서버가 칸 결과로 계산한다
4. **사람이 확인해야 다음 단계로 간다 (Human-in-the-loop).** 담당자가 비교표를 줄마다 확인해야 승인할 수 있다. 연구원 확인 사실과 AI 제안을 전달자료에서 나눠 표시한다.
5. **분야 용어 사전으로 배운다.** "주름 = 플리츠 = 절곡"처럼 같은 뜻 다른 말을 사전으로 넣어 놓친 특허를 줄인다. 현직자 확인으로 계속 고친다.

**경쟁사 대비 한 문장:** 키워트·윕스 같은 도구는 "더 잘 찾는 검색"이고, InPro는 "발명 접수부터 변리사 전달까지 사람 사이의 일을 잇고, 판단 근거를 남기는 도구"다. 검색·문서 생성이 겹치는 건 인정하고, 보완 요청·사내 승인·변리사 전달 사이의 재작업을 줄이는 게 차별점이다.

## 6. 시연 대본 (약 3분)

시연 분야: 가정용 공기청정기 필터의 형상. 예시 발명은 "표면적을 늘린 이중 주름 공기청정기 필터" (가상).

1. **소개 페이지 (`/`)** — 문서 더미에 마우스를 올리면 펼쳐지며 "근거 확인" 표시. "데모 시작하기" 클릭
2. **1단계 발명 접수** — 기본 정보 줄 오른쪽 끝의 작은 "예시 채우기"를 눌러 채움 → 작성 완성도 100%, 공개 D-21 경고 → "AI 검토 요청"
   - 말할 것: "연구원 메모를 그대로 넣으면 출원 검토용으로 정리하고 빠진 항목을 짚습니다."
3. **2단계** — 보완 질문 3개, "연구원에게 보내기" 미리보기 → "메시지 복사"
   - 말할 것: "메일로 몇 번 오가던 발명자 인터뷰를 질문 몇 개로 줄였습니다."
4. **3단계 선행기술 조사** — "선행조사 실행"
   - 검색 경로: "필터 특허 ○○○건 → 가정용·형상 ○○건 → … → 담당자 선택"
   - 1위 문헌 "왜 선정?": 동의어로 찾은 표시, 청구항 형광펜
   - "비교표 만들기" → **매트릭스**: 신규성·진보성 판정, 핵심 차별 구성. 칸을 눌러 원문 인용 보여주기
   - 말할 것: "AI가 '있다'고 해도 원문에 그 문장이 없으면 서버가 판단을 버립니다."
5. **4단계** — "검토서 초안 만들기" → 지표 카드와 AI 추천
6. **5단계** — "권리범위 설계안 만들기" → "핵심인데 우회가 쉬움" 경고 보여주기
   - 말할 것: IP팀장 인용 "경쟁사가 우회하기 어려운 어떤 권리를 만들 것인가"
7. **6단계** — 출원 방식 선택, 비교표 "확인" 체크, 승인자 입력 → "승인하고 전달자료 만들기" → 공문서 형식 전달자료

시연 팁
- AI 단계는 각 3~6초 걸린다. 기다리는 동안 말할 내용을 준비한다.
- 예시 문구와 수치("여과 면적 약 30% 증가", 발명자 이름)는 시연용으로 지어낸 내용이다.

## 7. 비즈니스 모델·가격 (기획안 7장)

- 가격 산정 원칙 (2차 멘토링): **담당자가 쓰는 시간 × 사람을 얼마나 줄이는지**로 정한다
  - 1건당 줄어드는 시간 = 수작업 시간 − InPro 사용 시간 (현직자 검증에서 측정: ○시간 → ○시간)
  - 월 절감 금액 = 줄어드는 시간 × 시간당 인건비 × 월 발명 건수 → 가격은 이보다 확실히 싸게
- 현재 요금안 (부가세 별도, 변리사 비용 제외): 유료 파일럿 99만 원/6주 · 기본형 59만 원/월(월 5건) · 확장형 119만 원/월(월 12건) · 건별 15만 원 · 로컬 설치형 별도 견적
- 기본형 기준 고객당 월 공헌이익 39만 원(약 66%), 월 고정비 1,500만 원 가정 시 손익분기 39곳 (가정치)

## 8. 보안 (예상 질문 1순위)

- #4가 두 번 짚은 걱정: 미공개 발명을 외부 AI에 넣는 것
- 두 가지 모드
  - **클라우드(기본):** 입력을 학습에 쓰지 않는 유료 AI API, 기업별 공간 분리
  - **로컬 설치형:** InPro와 AI 모델까지 회사 PC·사내 서버에 설치해 발명 내용이 밖으로 나가지 않음 (맞춤형 요금제)
- 솔직한 한계: 로컬 AI는 한국어·긴 문서 품질이 낮고 GPU 사양과 설치 부담이 있다. InPro는 AI 연결이 코드 한 곳(`lib/ai-client.ts`)에 모여 있어 모델만 바꾸면 두 모드를 모두 지원할 수 있다.

## 9. 실제로 되는 것 vs 아직 데모인 것 (심사 질문 대비)

**실제로 동작함**
- 6단계 전체 흐름 (Gemini AI 실제 호출), 원문 인용 서버 검증, 검색 설명, 매트릭스 판정, 승인 흐름, 변리사 전달자료 인쇄·Markdown 내보내기
- 공개 전 출원 알림, 개발 단계별 재조사, 용어 사전 검색, 정답지 재현율 측정 도구
- 입력 크기 제한 등 기본 보안 장치, 자동 테스트 33개

**아직 데모·계획 단계**
- 검색 데이터: 필터 특허를 팀원이 KIPRIS에서 수집 중 (그전까지는 1차 때 모은 출연연 특허 2,205건 데모 DB)
- 비교 깊이: 요약과 대표 청구항 기준 1차 검토 (전체 명세서는 아님). 최종 판단은 변리사
- 연구원에게 보내기: 메일 앱 열기·복사까지. 연구원 전용 답변 링크는 다음 단계
- 새로고침하면 작업 내용이 사라짐 (저장 기능 없음)
- 실제 고객 결제·파일럿 실적 없음, 가격과 시간 절감은 검증 목표치

## 10. 검증 계획과 결과 자리

- **현직자 데모 검증 (#1, 이번 주):** 필터 형상 데이터로 직접 사용 → 단계별 수작업 시간 측정, 비교표 줄마다 맞음/틀림, 1~5점 점수, 발표용 한마디
  - 결과: 수작업 ○시간 → InPro ○시간 / 비교 정확도 ○% / 점수 ○점 / 한마디 "○○"
- **검색 정확도:** 현직자가 고른 "꼭 나와야 하는 특허"를 상위 10건 안에서 몇 % 찾는지 (용어 사전 없이 ○% → 사용 ○%, 목표 85%)
- 확장 계획: 필터 형상 → 같은 필터의 소재·제조 → 차량용·산업용 필터 → 다른 가전 부품. 분야가 바뀌어도 "데이터를 좁히고 → 현직자가 검증하고 → 넓힌다"는 같은 절차

## 12. 예상 질문과 답

- **키워트와 뭐가 달라요?** → 검색·문서 생성은 겹친다고 인정한다. InPro는 보완 요청·사내 승인·변리사 전달 사이의 재작업을 줄이고, 판단 근거를 남긴다.
- **AI가 틀리면요?** → 원문에 없는 인용은 서버가 자동으로 걸러 "근거 부족"으로 표시하고, 담당자가 줄마다 확인해야 승인된다. 최종 판단은 변리사가 한다 (#4의 Human-in-the-loop).
- **미공개 발명을 AI에 넣어도 되나요?** → 기본은 학습에 쓰지 않는 AI와 기업별 공간 분리, 민감한 기업은 AI까지 사내에서 도는 로컬 설치형.
- **왜 필터만 해요?** → 멘토 조언대로 한 분야에서 현직자 검증으로 완성형을 만들고, 같은 절차로 넓힌다.
- **누가 돈을 내요?** → 특허팀이 없거나 겸임하는 연구개발 기업. 아직 파일럿 전이며 숫자는 검증 목표다.
- **검색이 단어 일치면 놓치지 않나요?** → 용어 사전으로 동의어를 함께 찾고, 정답지로 재현율을 재서 개선한다. 다음 단계로 의미 검색을 붙인다.
